# NOVA 企业与个人知识网络

NOVA 会把用户在真实任务中产生的输入、工作区文件、任务结论、交付物和已确认知识，组织成一套可追溯的本地 Knowledge OS，而不是另一份孤立的知识列表。

## Knowledge OS 的三层结构

1. **Ontology（定义）**：统一目标、输入、资料、交付物、确认知识、概念和能力的含义，以及它们允许建立的关系。这样不同 Agent 产生的知识可以进入同一套语义体系。
2. **Wiki（阅读）**：把图谱节点编译为自然语言知识页，默认展示摘要、已确认事实、可能联系和来源。普通用户先阅读内容，不必先学习复杂图谱。
3. **Rule Engine（判断）**：用确定性规则检查证据缺口、待确认映射、来源缺失和交付闭环。规则判断在本机完成，不调用模型、不消耗 Token，也不会自动修改文件。

Ontology、规则定义、Wiki 索引和 Markdown 页面会持久化到本机 NOVA 数据目录。图谱仍然是底层关系能力，但不再是用户唯一的入口。

## 用户可以看到什么

- **独立知识地图**：从认知中心一键打开独立窗体，不与任务执行界面混在一起。
- **知识首页**：默认以 Wiki 卡片展示可阅读内容，降低第一次使用的学习成本。
- **多层视图**：“关系地图”用于探索，“待确认关系”用于校准，“规则判断”解释系统建议，“完整网络”保留给高级用户。
- **知识空间**：每个工作区形成一个独立知识空间；用户也可以切换到“全部知识”查看自己的跨项目网络。
- **确定关系**：由文件、任务、对话和交付物直接建立，使用实线展示。
- **可能映射**：当两个知识对象共享多个关键概念时，NOVA 用虚线给出候选联系，同时展示置信度和推断依据；它不会被当作事实。
- **人工校准**：用户可确认或忽略候选映射；确认后升级为可靠关系，忽略后持久抑制同一错误推荐。
- **来源与上下文**：节点保留来源类型、来源名称、更新时间以及与其他节点的关系，便于回到原始证据。
- **自由探索**：用户可以搜索主题、点击节点、查看相邻知识，从局部线索逐步展开整张网络。

## 自动收录范围

当前版本在本机收录以下内容：

1. 用户提交给任务的文本输入；
2. 工作区中被知识索引支持的文件；
3. 任务目标、运行状态和交付物；
4. 已安装的 Skills、MCP、模型供应商等能力关系；
5. 用户手动添加的知识。

API Key、Bearer Token、密码和常见密钥赋值会在进入图谱前进行本地脱敏。

## 隐私与删除边界

- 数据与生成的 Wiki 页面默认保存在本机 NOVA 数据目录，不因整理知识自动上传云端。
- “当前空间”不会沿跨空间推断关系读取其他工作区的私有节点。
- 删除一个输入节点只会删除图谱中的收录节点及其派生映射，不会偷偷删除原任务、聊天记录或工作区文件。
- “全部知识”是当前本机用户自己的全局视图，不等于企业多租户共享空间。

## 当前能力边界

这是一套本机个人/企业单席位知识网络。真正的企业多人协作还需要独立实现账户、组织空间、成员权限、端到端加密、共享审批和审计策略；当前版本不会把逻辑知识空间宣传成已经具备多租户隔离的云知识库。

## 后续方向

- 支持批量审核、重命名和补充关系说明，让网络校准更高效；
- 将高频关系沉淀为可复用 Skill 或行业 Agent 的私有知识包；
- 增加时间轴、关系类型筛选、图谱快照和差异对比；
- 在具备组织权限系统后，支持经审批的团队知识共享。
