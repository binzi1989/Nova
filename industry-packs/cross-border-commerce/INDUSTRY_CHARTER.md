# NOVA Cross-Border Commerce · Industry Charter v0.3

## 服务对象与核心任务

- 目标客户：需要判断商品是否值得进入海外市场的跨境卖家与商品团队。
- 核心任务：在信息不完整时中立识别商品，研究目标市场需求，形成可追溯的需求适配判断，并设计最低成本的验证行动。
- 主要耗时工作：期初选品、消费者和竞品研究、本地化判断、商业可行性计算、宣传内容与测试设计。
- 核心结果：回答“消费者是否可能需要它、为什么、哪些证据支持或反对、下一步怎样验证”，而不只回答“毛利是多少”。

## 为什么做这个任务

它同时覆盖 NOVA 已有的后台研究、知识整理、多 Agent 编排、文件交付、审批和证据链能力，
而且结果可以被卖家直接评价：是否值得测试、为什么、什么证据可能推翻判断、先测试什么、哪些结论仍待验证。

历史商品案例只用于离线评测和回归验证，不得作为新任务的默认商品、品牌、规格、价格、市场或平台。

## 中立商品识别规则

1. 每轮识图只使用本轮附件、用户文字和本轮检索到的可核实来源。
2. 输出分为 `OBSERVED`（图中直接可见）、`INFERRED`（视觉推断）、`UNKNOWN`（无法确认）三类。
3. 无法唯一识别时，给出最多三个候选品类、各自置信度、区分它们所需的最小问题。
4. 商品身份置信度低于 55/100 时，最高只能给出 `IDENTIFY-FIRST`，不得进入确定性选品结论。
5. 不得从历史案例补齐品牌、容量、功率、材质、售价、目标国家、平台或人群。

## 固定输入

必需：

1. 至少一项商品线索：图片、名称、链接、规格或用途描述。
2. 目标国家/地区和预期销售渠道；缺失时先请求选择，不继承历史任务。

进入完整商业闸门前建议补充：

1. 可核实的规格、认证、包装和履约信息。
2. 目标售价、采购成本、物流、平台费用和预期毛利。
3. 竞品、评论、搜索趋势、社媒内容或历史投放数据。

财务缺失只会使“商业可行性”保持待确认，不应阻止需求、竞争、场景与验证方案分析。

可选：

- 竞品链接、现有视频、用户评论、库存、品牌素材和历史投放数据。

## 固定交付物

1. `product-passport.json`：商品身份、已证实事实、假设、未知项与来源。
2. `需求适配评分.json`：痛点、人群、频率、市场活动、竞争空间、差异化、内容可演示性、本地适配和风险维度。
3. `市场证据账本.json`：市场主张、来源、日期、新鲜度、冲突与健康分。
4. `市场进入建议.md`：GO-TO-TEST、CONDITIONAL-TEST、VALIDATE-FIRST、IDENTIFY-FIRST 或 NO-GO-FOR-NOW。
5. `最小验证计划.md`：优先验证的假设、测试对象、信号、预算/周期上限、继续和停止标准。
6. `落地利润情景.json`：数据充分时给出逐项成本、贡献利润率、盈亏平衡广告费率与 ROAS；否则保持待确认。
7. 目标人群、问题场景、替代方案、竞争空位、可验证卖点与反方理由。
8. 本地化、合规、信任、退货、售后和平台风险。

商品档案、需求适配、证据账本和利润情景必须优先调用 NOVA 的确定性 Commerce Tools 生成，不允许由模型心算或
自行判断证据是否过期。缺少输入时保留未知字段并给出最小问题，不得填入猜测值。

## 市场需求预判框架

需求判断至少覆盖十二个维度：痛点强度、人群范围、使用频率、市场活动、竞争空间、商品差异化、内容可演示性、
本地场景适配、信任门槛、合规风险、退货/售后风险和季节稳定性。财务结果作为独立维度参与最终建议，不能替代需求判断。

- `GO-TO-TEST`：证据支持进入受控测试，但不等于规模化成功。
- `CONDITIONAL-TEST`：存在吸引力，但必须限制预算并先验证关键风险。
- `VALIDATE-FIRST`：商品基本明确，但市场证据覆盖不足。
- `IDENTIFY-FIRST`：商品身份或用途尚不能可靠确认。
- `NO-GO-FOR-NOW`：现有证据显示需求弱、差异不足或风险过高；新证据出现后可重评。

禁止输出确定销量、GMV、转化率或“必爆”承诺。分数必须同时显示证据覆盖率、证据质量和不确定性惩罚。

## 权限和诚实边界

- 公开网页研究可以后台执行，但保存账号、登录、发布、投放和购买必须单独授权。
- 不得把卖家页面描述当作实验事实，不得虚构销量、GMV、转化率或 TikTok 热度。
- 未确认的规格、认证、性能、安全性、耐用性和适用范围不得写入广告承诺。
- 所有本地化广告在发布前需要目标市场母语或本地运营人员确认。

## MVP 成功标准

- 卖家能在 10 分钟内看懂结论并找到下一步动作。
- 关键事实全部有来源，事实与推断不会混写。
- 对同一证据重复运行时，核心需求判断与证据口径保持一致。
- 更换商品图片后不得残留上一商品的名称、规格、价格或结论。
- 最小验证计划能在明确预算/周期边界内执行，并具有继续与停止标准。
- 记录人工修改点，逐步沉淀为评测，而不是直接训练核心模型。

## A2A 路线

MVP 内部先使用可观察的角色工作流。第一条工作流稳定后，再把市场研究、内容生成和
本地合规审查暴露为独立 Agent Card，通过 A2A 交换任务、进度和交付物。A2A 不得成为
完成首个客户结果的前置阻断项。
